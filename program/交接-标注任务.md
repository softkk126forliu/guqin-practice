## 2. 三个致命陷阱（务必先读，否则会重蹈覆辙）

### 陷阱一：不要用录音一致率评判八度

`audio_score_check.py` 的 `aud_pitch` 取的是同音级**最强**的分音，
在泛音音与空弦低音区必然取到泛音而非基频：

```
C2(36) 的 2 次泛音是 C3(48)，D2(38) 的 3 次泛音是 D4(62)
60.51  C2:4.7  C3:4.3  E3:4.2    ← C2 比 C3 还强，基频确实在
```

工具已加 `aud_base`（该音级**出现过的最低**八度 = 基频优先），
八度判定按音色分基准：泛音用最强八度、散按用基频。
**报告里的「八度判定」列才是可用的。**

### 陷阱二：简谱点标记的语义不是「相对基准区」

之前把 `d1`（下方点）定成基准区 `[48,59]`，是**从页面值反推的循环论证**。
正确：点/线表示**相对简谱默认区的八度偏移**，一个八度一档。

### 陷阱三：AI 视觉读减字谱徽位不可靠

减字谱的字位与简谱音**不是一一对应**（字位含「吟猱」装饰与「舟作」等文字说明，
程序检测的减字谱 x 与简谱音 x 明显错位）。

**不要尝试让 AI 直接读徽位。** 徽位改用录音基频反推（见第 4 节），
人只复核异常点。

### 怎么读 marks 图

- **红色数字** = 音序号，对应 spec 里该排 `notes[]` 的下标（1 起）
- **紧贴简谱数字下方的短横线** = **下加线**，条数 = 减八度数（0 条 = 默认区）
- **跨多个数字的长横线** = 延音线，**忽略**
- **数字上方的 ○○** = 泛音（青城用两个圈）

```
序号1 「0」  下方长线（延音线，忽略）

序号3 「2」  下方 1 条短线 → 低 1 个八度，上方 ○○ → 泛音
序号4 「0」  下方长线（忽略）
序号5 「6」  下方 1 条短线 → 低 1 个八度，上方 ○○ → 泛音
序号6 「1」  下方 1 条短线 → 低 1 个八度，上方 ○○ → 泛音
```

## 4. 第二步：读出下加线条数，写进 spec

### 目标字段

给每个 note 增加两个字段（**先只做 `oct_shift`，`hui` 留空**）：

```json
{"p": "1", "oct_shift": -1, "harm": true, "x": 16.25, "w": 3.0, "d": 1}
```

- `oct_shift`：相对简谱默认区的八度偏移，**0 / -1 / -2**（0 = 无下加线，-1 = 一条线…）
- `hui`：徽位，**本轮先不填**（留空或省略）

### 简谱默认区是什么

| 谱 | 定弦 | 默认区（oct_shift=0） | 音级→弦 |
|---|---|---|---|
| 春风 | bB 调 | 中音区 `[48,59]` | 1→一弦 … 7→七弦 |
| 青城 | 1=C 正调 | 中音区 `[48,59]` | 同上 |

> 例：青城排 1 音 2 是「1」带一条下加线 → `oct_shift = -1`。
> 「1」对应三弦，正调空弦 C2(36) → 默认区 C3(48) → 低一八度 = C2(36)。
> **若该音是空弦（减字谱无徽位），最终音高就是 C2(36)。**

## 9. 徽位怎么补（下一阶段）

工具已经能给出**录音基频**（`aud_base`）。
算法：已知 `oct_shift` + 录音基频 → 反推弦与徽位 → 填进 spec。

```
页面发声 与 aud_base 相差 8 度 → 规划值应该是 base + 12（或 -12）
规划值落在 [弦的空弦音高, 下一弦的空弦音高) 区间 → 确定弦
规划值 - 空弦音高 = 徽位音程 → 查表得徽位
```

徽位音程表（半音，相对空弦）：
`一徽5 二徽7 三徽10 四徽12 五徽14 六徽17 七徽19 八徽24 九徽26 十徽28 十一徽30 十二徽31 十三徽32`

> 徽位需要人工复核几处边界（八度处的十二/十三徽），别全信自动推算。
