# 古琴跟谱页 ↔ 示范音频 发音一致性检查

只依赖 `numpy`、`scipy` 和系统里的 `ffmpeg`，不需要 librosa。脚本在 `scripts/`：

| 脚本 | 作用 |
|---|---|
| `audio_score_check.py` | 主程序：自动对齐、逐音判定，输出 `.md` / `.csv` / `.json` 报告 |
| `pitch_track.py` | 逐帧打印某段录音的候选音高（带八度），人工复核"可疑/不一致"时用 |

## 1. 准备

1. 确认页面的音从哪里读：
   - 首选成品 HTML，脚本会读其中的 `const CELLS`（每格 `pcs` 音级 0–11、时值 `d`、是否泛音 `harm`）和 `const ROWS`（每排 `bpm`）。这就是页面"模拟弹奏"实际发的音。
   - 也可以用 spec JSON（`rows[].notes[].p` 简谱数字 + `tonic`），用 `--spec` 和 `--tonic`。
2. 确定录音里哪一段对应页面。一页书通常只对应整首录音的一部分：用 `--start/--end` 框一个宽一点的窗口（比如页面标称时长的 1.5–2 倍），算法会自己找起点和终点。
3. 有 PDF 琴谱的话，先渲染页面看一眼（`fitz`/PyMuPDF：`page.get_pixmap(dpi=110).save(...)`），确认页面对应 PDF 的哪一段，并记下**倚音（小字）、滑音弧线、"上/下/进/退/绰/注"、撮（上下叠写）**的位置，复核时要用。

## 2. 运行

```powershell
python .agents/skills/guqin-audio-check/scripts/audio_score_check.py `
  --page "春风/古琴跟谱 · 春风_agron_my.html" `
  --audio "春风/春风_最贴切示范_Chinese_Guqin_music_春风_古琴.mp3" `
  --end 120 --out <输出前缀>
```

可选：`--transpose N`（强制移调，默认 auto）、`--tune C`（强制调音偏差 cents）。
报告不要写进仓库的曲目目录，放到 scratch 或 artifact 目录，除非用户要求保留。

## 2.1 改模板后必跑：一致性校验

`audio_score_check.py` 的 `page_midis()` 是模板八度规划逻辑的**手工复刻**。
两边一旦分叉，报告里的 `page_sound` 就与页面实际发声不符，所有基于报告的结论都会失真。

**改了 `page.template.html` 的八度规划后，先跑这个**：

```powershell
python .agents/skills/guqin-audio-check/scripts/check_sync.py `
  --page "春风/古琴跟谱 · 春风_agron_my.html"
```

它**不依赖"复刻是否写对"** —— 而是从模板文件里真实提取规划代码块，用 node 执行它，
再与 `page_midis()` 的输出逐音对账。退出码 0 = 一致，1 = 有分歧（打印明细）。

依赖 `node` 在 PATH 中。没装 node 就只能靠人肉对账，务必格外小心。

## 3. 算法（为什么这样做）

1. **调音偏差**：录音的谱峰相对 A440 做加权圆均值。古琴很少正好在 A440（《春风》示范约 −32 cents，A4≈432Hz），不先校正，按音会被分到相邻半音。
2. **音调性显著度色度**：只保留明显高出邻域的谱峰（压掉拨弦和走手的宽带噪声，这些噪声在起音帧会让 D3/E♭3/E3 等相邻半音一起冒头），再做 6 次谐波加权求和得到 MIDI 36–96 的音高显著度，最后折叠成 12 个音级。比普通 chroma 少了泛音的五度、三度干扰。
3. **移调判断**：拿全段色度和页面音级直方图做 12 种移调的相关。同调（0）最高说明录音和页面同调；如果其它移调明显更高，说明录音换了调或页面 `tonic` 错了。
4. **事件**：音频事件包括两类：拨弦起音（对数谱正向谱流）和"走手音级变化点"（没有新起音，但主音级稳定变成另一个，对应上/下/进/退等）。
5. **带节奏约束的动态规划对齐**：页面音按顺序对上一串递增的音频事件，音频起止自由。代价由三部分相加：
   - 音级不像：`1 − cos(页面模板, 事件色度)`
   - 跳过的音频事件：倚音、打圆、页面没画的装饰音会被跳过，代价按起音强度计
   - 节奏偏离：`|log(实际间隔 / 页面期望间隔)|`，期望间隔由每排 bpm 和整体速度倍率算出，第二遍用第一遍估出的倍率
   页面音最多连跳 2 个，每跳一个代价很高。
6. **逐音判定**：取每个对齐点起音后 50–350ms 的色度，减去起音前的余音，看页面期望的音级排第几：
   - 排在前 `n` 位（`n` 为同时发的音数）为 **OK**
   - 排在前 `n+2` 位为 **可疑**
   - 其它为 **不一致**
   - 没对上任何事件为 **缺失**
   同时报告：页面实际发声音高（`page_sound`）、HUD 显示音高（`page_hud`）、录音最强具体音高（`pitch`）、录音同音级最强八度（`aud_pitch`）、这个音是拨出来的还是走出来的、和下一个页面音之间多出来的较强拨弦。

## 4. 两层检查与人工复核

检查必须分两层进行，缺一不可：

### 第一层：音级检查（Pitch Class 0–11，不分八度）

- 核对简谱唱名 `1..7` 与 `1=调` 是否与录音、PDF/书页一致。
- 留意减字谱里的 `从「再作`、`再半作`：在简谱+减字谱对照谱中，这通常是下方减字谱对上方已展开简谱的省写，而非额外反复。
- 自动判定只是初筛。**"可疑/不一致"必须用 `pitch_track.py` 人工复核**后才能下结论：

```powershell
python .agents/skills/guqin-audio-check/scripts/pitch_track.py --audio <录音> --from 59.7 --to 63.4 --tune -32 --step 3
```

常见的"假不一致"（并不是页面写错）：

| 现象 | 原因 | 复核办法 |
|---|---|---|
| 期望音排第 2，第 1 是它的下四度/上五度（如期望 F、听到 C/F） | 泛音音色里另一个分音很强 | 期望音在持续帧里稳定存在，就算一致 |
| 低音撮（如 2+5 = C3+F2、3+6 = D3+G2）只认出一个音 | 低音弦的基频弱，主要靠 3 次、5 次泛音 | 看是否出现 F2 的 A4（5 次）、G2 的 B4/D4 等泛音 |
| 滑音弧线下的第二个音判不出来，或者听到相邻半音 | 走手音没有新起音，音量小，音高是滑过去的 | 看持续帧里音高是否最后停在期望音上 |
| 页面音前有多个很密的"多出的拨弦" | PDF 上的倚音（如 ⁶²³6、³⁶¹3），页面按设计省略 | 对照 PDF 小字 |
| 一串同音快速反复（如 666）中某个音缺失 | 起音间隔 < 60ms，或指法连得太紧 | 不算发音错误 |

能下"真不一致"结论的情况：期望音在整个音的持续帧里都不出现，录音里稳定出现的是另一个音级，而且 PDF 上也写的是录音那个音（说明页面 spec 抄错了），或者 PDF 和页面一致、但录音演奏者确实改了音（属于版本差异）。

### 第二层：八度与页面合成音高检查（MIDI / Octave）

音级一致不代表页面模拟弹奏发音正确，还必须对照报告里的 `页面发声`（`effMidi`）、`page_hud`（`MIDI`）与琴谱高低音点（`·` / `:` / `.`）、减字谱弦徽及 `录音同音级八度`（`aud_pitch`），核对实际发声八度是否一致。注意排查跟谱页模板的三类典型八度问题：

1. **`spec.json` 缺少高低音点 + 贪心八度平滑 + `minM` 截断**：`spec.json` 的 `p` 仅存裸数字（不含高低音点），模板靠上一音 `pv` 贪心平滑猜八度，且散按音下限为 `minM = 40`（E2，高于一弦 C2=36、二弦 D2=38）。这会在高音泛音跳进、八度大跳（如 `3̇→3̣`）及一至四弦低音散按段产生 1–2 个八度偏差。
2. **双音撮八度折叠**：模板用 `best.m - dd` 固定把第二音放在第一音下方一个八度内，遇到十度大撮（如 `6/3̣` = G3+D2）时会把低音抬高一个八度（变成 G3+D3）。
3. **泛音 HUD 与发声差八度**：泛音段 HUD（`drawLens`）显示 `MIDI[i]`，而合成器 `buildKSBuffer` 加了 `+12`（`Math.min(79, midi + 12)`），导致 HUD 显示比页面实际发声低一个八度。

## 5. 输出给用户的结论

1. 整体（分两层）：调音偏差、是否同调、页面在录音中的时间段；第一层音级 OK/可疑/不一致数量与复核结论；第二层页面实际发声八度与 HUD 偏差统计。
2. 按排列出复核后仍有问题的音（音级差异或八度偏差）：录音时间、页面发声/HUD、录音听到的、PDF/行图写的，以及原因判断（页面错 / 模板八度规划限制 / 版本差异 / 机器误判）。
3. 附带（可选）：每排录音实际 bpm 和页面 bpm 的对比，用来调 `bpm` 或时值。
4. 只报告，不要自动改 spec 或 HTML；用户确认后再按 `guqin-score-page` skill 改 spec 并重跑 build。
