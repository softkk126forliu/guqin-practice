# 标注任务说明

> 这是**执行者**的作业书（当前执行者以 Antigravity 为例；换任何 agent 规则不变）。
> 具体怎么用工具自己判断；
> 读谱的实测经验在 `交接-标注任务.md`。
>
> 角色约定：**执行者**（标注、改代码与正文、提交）、
> **评审者**（复核、提修正意见、出报告）、**观察者**（合并、控制节奏）。
> 本文件里「你」= 执行者。

## 目标

古琴谱的绝对音高 = **弦的空弦音高 + 徽位音程**。
现在页面靠猜八度（`targetCenter` + 上一音平滑），错得很厉害。

你的任务：**把谱面的八度信息读出来写进 spec，让八度变成确定的。**

## 四条硬规矩

1. **读不准就标 `null`，不要猜** —— 留白会进「待人工确认」清单；猜错会变成确定性错误
2. **只动八度相关字段** —— `p` / `x` / `w` / `d` / `harm` 动了就是抄错谱
3. **不要用录音一致率评判八度** —— `aud_pitch` 取的是最强分音（泛音），空弦低音区会得出反向结论
4. **不直推 main** —— 走分支 + PR

## 起点

- 工具：`crop_rows.py`（裁带标号的排图）、`verify_annotations.py`（校验标注质量）、
  `check_sync.py`（校验检查脚本与模板未分叉）
- **青城排 3 是已跑通的样板**，先照着做

## 顺序

青城排 3（样板）→ 排 8 → 排 9 → 排 2/5/6 → 排 10-14。
排 1、15 是全泛音排，八度由徽位决定，`oct_shift` 用不上。

一次做 2–3 排就提交一次。

## 交作业

- 汇报要含：**读数表**（每音的谱面数字 / 八度信息 / 标注值 / 页面发声音高）、
  **验证结果**、**待人工确认的音**
- push 分支并开 PR（base = `main`），把链接告诉观察者
- 读不准就明说，别把猜测写进 spec

## PR 正文 = 你的读数表，要跟代码一起改

PR 正文里的读数表是这次提交**对外的说明**，必须和 spec 逐音一致。

- 被评审者要求修正后，**除了改 spec 和重跑 build，还要同步改正文里的读数表**
- 正文里的「修正说明」段落要写清：哪几个音、原值、新值、依据
- 别用 `gh pr edit --body` 整篇重写 —— 会丢掉原有内容，**只能定点替换**，
  先 `gh pr view <n> --json body --jq '.body'` 导出，改完再 `--body-file` 回写

流程顺序（被纠正时照做）：

```
你初版 → 评审者提修正 → 你改代码 + 同步正文 → 评审者复核通过 → 观察者合并
```

正文没同步就交回，评审者只能给「有条件通过」，且合并后补改成本更高。
