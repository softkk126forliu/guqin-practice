# 谱面高低音点规则 —— 从扫描谱中提取八度信息

方案 A 的技术底稿：如何从 `春风.pdf` 的扫描谱面读出每个音的八度，
以及由此得到的一个重要结论——**示范录音的八度并不可靠，验证基准应该用谱面**。

## 1. 最佳输入源是行图，不是 PDF

`program/春风/out_cf_agron_my/my_cf_rows/row_N.png`（2800×N 像素）是从 PDF 对应区域
裁出的原始谱面，比 PDF 扫描件（2799×3848、7 页）好得多：

- 分辨率高、无缩放
- 6 排各一张，已定位
- **与 spec 的音符坐标直接对应**：行图像素 x = `note.x / 100 × 2800`
- 每排含简谱（上）与减字谱（下）两层

PDF 页面坐标也能用：spec 每个 row 有 `box: [x0, y0, x1, y1]`（PDF 归一化坐标），
第 1 排简谱的像素 y 范围为 926–1112。

## 2. 谱面的记号含义

简谱数字旁有两类小标记：

| 记号 | 含义 | 位置 |
|---|---|---|
| **空心圈 ○** | 泛音徽位记号 | 数字上方，与泛音段同时出现 |
| **实心点 ●** | **八度点** —— 个数决定八度区 | 数字上方或下方 |

**上下叠写的两个数字 = 撮（同时奏）**，对应 spec 的多音 `p` 数组。
数字上方/下方的小号数字组（如 623、361、32）是装饰或技法标注，**不是独立音符**。

## 3. 八度规则（实测校准）

设该音的音级为 `pc`（0–11），数字旁的**实心点个数**为 `n`：

```
n 个实心点 → 规划 MIDI 落在 [48 + (n-1)×12, 59 + (n-1)×12]
具体取值 = 该区间内与 pc 匹配的唯一值
```

即：

| 实心点数 | 规划 MIDI 区间 | 泛音发声（+12） |
|---|---|---|
| 1 | 48–59 | 60–71 |
| 2 | 60–71 | 72–83 |
| 3 | 72–83 | 84–95 |

**点的上下位置不影响音高**，只影响外观排布。

### 校准样本（排 2，15 个音，方案 B 后页面八度全部正确）

```
谱面: 6(○●) 3(○●) 6(○●) 7(○●) | 3(○●●) 2(○●●) | 1(○●) 7(○●)
规则: G3    D3    G3    A3    | D4      C4     | Bb3   A3
发声: G4    D4    G4    A4    | D5      C5     | Bb4   A4
页面: G4    D4    G4    A4    | D5      C5     | Bb4   A4   ← 12/12 吻合
```

## 4. 关键结论：方案 B 被谱面独立验证

排 4 泛音段（音 1–10）谱面标记为 `○+●`（1 个实心点）→ 规则给出规划 MIDI 在
48–59，即 D3(50)；泛音发声 = 50 + 12 = **D4(62)**。

- 方案 B **改动后**页面发 D4 ✅ 与谱面一致
- 方案 B **改动前**页面发 D5 ❌ 与谱面不符

**即方案 B 的方向由谱面独立证实，不依赖录音。**

排 4 散按段（音 11–19）谱面为数字**下方** 1 个实心点 → 规划 MIDI 48–59，
页面给 C3(48)/D3(50) ✅ 同样吻合。

## 5. 重要警示：示范录音的八度并不可靠

对照排 5：谱面全部是**单独的实心点**（1 个）→ 规则给出规划 MIDI 48–59，
即页面给的 G3(55) —— **页面与谱面一致**。

但 `audio_score_check.py` 的 `aud_pitch`（录音同音级最强八度）报 G4(67)。

同样地，排 4 音 1、2 等在录音里也出现与谱面相反的八度。

**结论**：录音是 AI 生成的示范音频（`Chinese_Guqin_music_*`），其八度选择
不完全遵循古琴谱面，且 `aud_pitch` 判定本身也受泛音干扰。

**因此，以 `aud_pitch` 为基准的"43% 八度偏差"高估了页面的实际错误率。**
方案 B 带来的"42/74 → 58/74"提升中，一部分可能只是与噪声录音对齐。

**后续验证应以谱面为基准**，而不是录音。

## 6. 对方案 A 的修正

原设想：人工标注每个音的**绝对八度**（约 250 个音）。

修正后：只需标注**实心点个数**（0/1/2/3），其余由规则推导。

优点：
- 点数是客观特征，人眼/视觉模型都容易判读，比判断绝对八度可靠
- 可自动化 —— 已实现连通域检测（空心圈用"有内洞"判定，实心点用尺寸 + 无洞判定）
- 标注量小得多：多数音只需记一个数字

## 7. 自动检测的现状与噪声

已实现的检测器（连通域 + 洞检测 + 按 x 聚类）能把 6 排的点标记提取出来，
规则在排 2、3、6 上验证良好（11/12、1/2、8/9）。

主要噪声来源：
1. **上下双行简谱**：排 4、6 的简谱分上下两排（泛音上排、散按下排），
   标记会被聚到同一组
2. **撮的上下叠写**：一个音有两个数字，各带自己的标记
3. **上标装饰组**：小号数字组被误认为标记
4. **点标记漏检**：聚类阈值 40px 过宽时会合并相邻音的标记

改进方向：按 y 坐标分层（已在验证脚本中尝试，一致率从 60% 提到 77%），
再配合视觉模型逐排校对。

## 9. 修正后的结论（2026-11-21）

用谱面规则复核后，**PR #13 的散按目标中心需要改回 52**。

### 双基准对比（57 个已确认谱面读数的音）

| 方案 | 谱面基准（权威） | 录音基准（AI 生成，有噪声） |
|---|---|---|
| PR #12 基线 泛音60/散按52 | 37/57 = 64% | 42/74 |
| PR #13 泛音52/散按62 | 46/57 = 80% | 58/74 |
| **修正 泛音52/散按52** | **56/57 = 98%** | 49/74 |

录音基准下降的原因见第 5 节：示范音频的八度不完全遵循谱面。
**谱面是演奏的唯一依据，故以谱面为准。**

### 为什么两者共用中心 52

- 泛音段：数字上方 1 个实心点 → 规划 MIDI 落在 48–59，发声由合成器 +12 到 60–71
- 散按段：无点或下方 1 个点 → 发声落在 48–59

即**规划值层面两者同处 48–59**，所以目标中心统一为 52（E3）。

### 贪心算法的剩余局限

即使目标中心正确，贪心仍可能出错。排 6 音 2 谱面标了上方点（应在 60–71），
但因前一个音把 `pv` 锁在低音区，贪心仍选了低音区。

**根治仍需方案 A**：把谱面的点标记写进 spec，让模板直接采用，
不再靠 `pv` + `targetCenter` 猜测。

### 读谱时的注意事项

- **以行图为准，不要用 PDF**：行图来自书页原图，是 spec 的直接来源；
  PDF 是另一个来源，记法与排版都不同（早期用 PDF 读出的点标记与行图不一致）。
- **上下叠写的两个数字是撮**，对应 spec 的多音 `p` 数组，不是两个音符。
- **数字上方/下方的小号数字组**（623、361、32）是装饰或技法标注，不是独立音符。
- **斜撇（´´）是倚音记号**，不是八度点。
