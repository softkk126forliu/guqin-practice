# 评审记录

## 这个目录干什么

每次评审一个标注/功能 PR，在这里留一份评审报告。**评审报告随 PR 一起进仓库**，
所以：谁评审的、看了什么、发现了什么、怎么处理的、结论是什么 —— 全程可追溯，
不依赖聊天记录。

## 命名

```
文档/评审记录/R<PR号>-<YYYYMMDD>-<主题简述>.md
```

例：`文档/评审记录/R21-20261122-青城排5-6标注.md`

## 三条原则

1. **结论必须挂数字** —— 「看着对」不算，必须有脚本输出或人工复核记录
2. **问题分级** —— 高（影响正确性）/ 中（影响可维护性）/ 低（风格），只有高等级必须本次修
3. **不推翻已验证的规则** —— 评审若要推翻某个结论，必须给出新的独立证据
   （谱面判读 / 减字谱徽位 / 录音基频），不能只靠推理
