# 评审记录

每次评审留一份报告，随 PR 进仓库 —— 谁评审的、看了什么、发现了什么、怎么处理的、
结论是什么，全程可追溯，不依赖聊天记录。

命名：`R<PR号>-<YYYYMMDD>-<主题简述>.md`

## 报告要写清

- **审查范围** —— 改了哪些文件、多少规模、涉及哪些排
- **客观验证数据** —— 直接贴脚本输出
- **人工复核抽样** —— 挑几个音对着谱面核，说明依据
- **发现的问题** —— 分高/中/低三级，写明处理方式
- **结论与遗留** —— 三选一：通过 / 有条件通过 / 打回

## 三条原则

1. **结论必须挂数字** ——「看着对」不算，要有脚本输出或人工复核记录
2. **问题分级** —— 只有高等级（影响正确性）必须本次修
3. **不推翻已验证的规则** —— 推翻必须给出新的独立证据，不能只靠推理
