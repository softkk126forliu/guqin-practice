## 2. 最初的问题描述

用 `guqin-audio-check` skill 对照《春风》跟谱页与示范录音实测，发现页面"模拟弹奏"发出的音高
与录音存在系统性偏差。当时的统计（**基于录音，数字偏高**）：

| 指标 | 当时实测值 |
|---|---|
| 参与判定的音 | 97 个（第 1–6 排）|
| 音级一致（OK） | 71 |
| 可疑 | 17 |
| 不一致 | 9 |
| 八度不一致 | 32 / 74（43%）|
| 调音偏差 | −32.2 cents（A4 ≈ 431.9 Hz）|
| 移调 | 0（与页面同调）|
| 时间倍率 | 0.93（录音比页面 bpm 慢约 7%）|

音级（pitch class）基本是对的，问题集中在**八度**。

## 3. 定位到的四个缺陷及最终状态

### 缺陷 1：泛音 HUD 与实际发声系统性差八度 ✅ 已修（PR #12）

`buildKSBuffer` 对泛音统一 `+12`，但 HUD 显示的是八度规划值 `MIDI[i]`，两者相差恰好一个八度。

实测：**39 个泛音音中 39 个 `page_sound − page_hud == 12`（100%）**。

修法：提取 `effMidiOf(midi, isHarm)` 供 HUD 与合成器共用。
修后：**39/39 → 0/39**。

### 缺陷 2：双音撮八度折叠 ✅ 已修（PR #15）

原模板把撮的第二音固定按半音数距离放在第一音下方（`best.m - dd`），遇到十度大撮时低音会被抬高。

方案 A 落地后，**撮的每个音改为在自己的八度区间内按各自音级取值**，不再折叠。
春风 13 个撮全部带有点标记，因此全部走确定路径 —— **遗留 0 个**。

### 缺陷 3：散按音下限截断 + 贪心八度平滑 ⚠️ 部分不成立

原判断：`minM = 40` 排除了古琴一弦 C2（36）、二弦 D2（38），是偏差来源之一。

**实测推翻**：把 `minM` 放宽到 36，正确数不变（58/74）。minM 不是瓶颈。
真正的原因是**音区先验方向设反**（见 PR #13/#14）：原值 `c.harm ? 60 : 52` 把泛音先验推高、
散按先验压低，导致整段散按音被压低一个八度。

最终 `targetCenter` 统一为 **52**。

### 缺陷 4：spec 不携带高低音点信息 ✅ 已修（PR #15，数据层根因）

`spec.json` 的 `p` 只存裸数字（如 `"6"`），不含简谱高低音点，模板完全依赖 `pv` 贪心猜八度。

**这一条是其它三条的根因**：只要 spec 补上点标记，很多八度猜测就不需要猜了。

修法见第 4 节。

## 4. 谱面八度点规则

从谱面行图（`program/春风/out_cf_agron_my/my_cf_rows/row_N.png`）判读得到。
**实心点的个数决定音高区，点的上下位置不影响；空心圈是泛音徽位记号。**

```
dot: u1 = 数字上方 1 个实心点, u2 = 上方 2 个, d1 = 下方 1 个
k  = (u 类 ? 点数 : 0) - (泛音 ? 1 : 0)
规划 MIDI ∈ [48 + k*12, 59 + k*12]
```

| 谱面标记 | 规划 MIDI 区间 | 发声 MIDI 区间 |
|---|---|---|
| 上方 1 个实心点（u1） | 48–59 | 60–71 |
| 上方 2 个实心点（u2） | 60–71 | 72–83 |
| 下方 1 个实心点（d1） | 48–59 | 48–59 |
| 无标记 | 48–59 | 48–59 |

- 上方点数决定八度区；泛音的发声由合成器另行 +12，故其规划区间下移一个八度
- 数字下方的点不改变八度（下点音与无点音同处低音区）
- **一个八度区间内同一音级只有一个 MIDI 值 → 有标记时八度唯一确定**

### 数据格式

```json
{"p": "6",   "dot": "u1", "x": 3.0,  "w": 3.8, "d": 0.5}
{"p": "6/3", "dot": "u1", "x": 28.0, "w": 5.0, "d": 1}
```

春风页 98 个音中 69 个带标记（u1×49、u2×10、d1×10）。

### 读谱要点

- **以行图为准，不要用 PDF**：行图来自书页原图，是 spec 的直接来源；PDF 是另一来源，
  记法与排版都不同（早期用 PDF 读出的点标记与行图不一致，导致过一次误判）
- **上下叠写的两个数字是撮**，对应 spec 的多音 `p` 数组，不是两个音符
- **数字上方/下方的小号数字组**（623、361、32）是装饰或技法标注，不是独立音符
- **斜撇（´´）是倚音记号**，不是八度点
- 谱面行图像素 x = `note.x / 100 × 2800`

## 5. 重要警示：示范录音的八度并不可靠

`audio_score_check.py` 的 `aud_pitch`（录音同音级最强八度）**不能当作真值**：

- 示范音频是 AI 生成的（`Chinese_Guqin_music_*`），八度选择不完全遵循古琴谱面
- `aud_pitch` 本身的判定也受泛音干扰（对比 `pitch` 字段可见音级不符 22 个）

具体例子：**排 5 整排谱面无点标记**（→ 发声 48–59），页面给 G3 与谱面完全一致，
但 `aud_pitch` 报 G4。

**因此以 `aud_pitch` 为基准的偏差率会高估页面的实际错误率。**
PR #13 最初「42/74 → 58/74」的提升中，一部分实际是向噪声录音对齐；按谱面复核后，
散按目标中心需要改回 52（已在 PR #14 修正）。

**后续验证一律以谱面为基准。**

## 6. 顺带修掉的两个既有缺陷

1. **音高上限截断**：`effMidiOf` 的 `Math.min(79, midi + 12)` 会把泛音的 A5(81)/Bb5(82)
   截成 G5(79)，造成音级错误（实测 4 个音受影响）。方案 A 把规划值推到高区后暴露出来。
   上限改为 83（B5）。
2. **`dotZone()` 漏掉 d1**：初版只处理 `u` 前缀，`d1` 回落到贪心，被 `pv` 锚定带偏
   （排 6 音 13 因此高了八度）。

## 7. 工程保障：模板一致性校验

`audio_score_check.py` 的 `page_midis()` 是模板八度规划逻辑的**手工复刻**。
两者一旦分叉，复测报告里的 `page_sound` 就与页面实际发声不符，所有基于报告的结论都会失真
（PR #12 的 HUD 修复、PR #15 的 d1 修正都因此反复排查）。

新增 `check_sync.py` —— **从模板文件里真实提取八度规划代码块，用 node 执行它**，
再与 `page_midis()` 的输出逐音对账：

```powershell
cd program
python .agents/skills/guqin-audio-check/scripts/check_sync.py `
  --page "春风/古琴跟谱 · 春风_agron_my.html"
```

输出：

```
模板: .agents/skills/guqin-score-page/templates/page.template.html
页面: 春风/古琴跟谱 · 春风_agron_my.html
可比音数: 97
✓ 完全一致 —— 检查脚本的复刻与模板逐音相符
```

已写入 `SKILL.md`，作为「改模板后的必跑项」。

## 10. 人工复核提示

「可疑」与「不一致」中有一部分是**假不一致**，复核时注意（详见 skill 第 4 节）：

- 泛音音色里另一个分音很强 → 期望音在持续帧稳定存在即算一致
- 低音撮（2+5、3+6）基频弱，靠 3 次/5 次泛音 → 看是否出现对应泛音
- 滑音弧线下的第二音没有新起音，音高是滑过去的 → 看持续帧是否停在期望音
- 页面音前多出的密拨弦是 PDF 上的倚音，页面按设计省略
- 同音快速反复（666）中某个音缺失不算发音错误

能下「真不一致」结论的条件：期望音在整个音的持续帧里都不出现，
录音里稳定出现的是另一个音级，且谱面写的也是录音那个音
（说明 spec 抄错了），或谱面与页面一致但演奏者确实改了音（版本差异）。
